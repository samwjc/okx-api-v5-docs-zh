OKX 流动性增强计划引入了新的**只挂单订单类型（ELP）**，旨在提升非 API 用户的流动性并改善交易执行质量。ELP订单可以由所有用户下单，并且仅与非直接通过 OpenAPI 下单的吃单进行匹配。

通过提供定向流动性，该计划为非 API 用户提供了新的经济激励，包括价格改善和滑点减少，同时维持了市场透明及完整性。

API变更如下。

*   ordType 请求参数新增枚举值`elp`以表示为特定币对下 ELP 订单

## 行情数据

*   在计算相关字段时，行情信息接口及频道将包含有效 ELP 深度及成交。
    *   [GET / 获取所有产品行情信息](/zh/order-book-trading-market-data-get-tickers)
    *   [GET / 获取单个产品行情信息](/zh/order-book-trading-market-data-get-ticker)
    *   [WS / 行情频道](/zh/order-book-trading-market-data-ws-tickers-channel)

  

*   当前已有的订单簿接口及频道不包含 ELP 深度。
    *   [GET / 获取产品深度](/zh/order-book-trading-market-data-get-order-book)
    *   [GET / 获取产品完整深度](/zh/order-book-trading-market-data-get-full-order-book)
    *   [WS / 深度频道](/zh/order-book-trading-market-data-ws-order-book-channel)
        *   `books/books5/bbo-tbt/books-l2-tbt/books50-l2-tbt`

  

*   新增订单簿频道`books-elp`，仅返回 ELP 订单，包含有效部分及无效部分（无效部分指 ELP 买单价格高于非 ELP 订单最佳买单价；或 ELP 卖单价格低于非 ELP 订单最佳卖单价）。用户需根据非 ELP 订单的最佳买/卖价区分有效部分和无效部分。
    *   `books-elp`：仅返回 ELP 订单，包含有效及无效部分。首次推400档快照数据，以后增量推送，每100毫秒推送一次变化的数据
    *   若订阅相同币对，新频道将和现有深度频道共享 seqId 机制

  

*   在计算相关字段时，K线接口及频道将包含 ELP 深度及成交。
    *   [GET / 获取交易产品K线数据](/zh/order-book-trading-market-data-get-candlesticks)
    *   [GET / 获取交易产品历史K线数据](/zh/order-book-trading-market-data-get-candlesticks-history)
    *   [WS / K线频道](/zh/order-book-trading-market-data-ws-candlesticks-channel)

  

*   交易接口及频道添加返回参数 source 以表示成交的 maker 订单是 ELP 订单或是普通限价单。交易频道聚合时也将考虑 source 字段。因此，该改动后，交易频道将根据每个 taker 订单的不同成交价格，不同成交来源来聚合消息。
    *   [GET / 获取交易产品公共成交数据](/zh/order-book-trading-market-data-get-trades)
    *   [GET / 获取交易产品公共历史成交数据](/zh/order-book-trading-market-data-get-trades-history)
    *   [WS / 交易频道](/zh/order-book-trading-market-data-ws-trades-channel)
    *   [WS / 全部交易频道](/zh/order-book-trading-market-data-ws-all-trades-channel)

**返回参数**
